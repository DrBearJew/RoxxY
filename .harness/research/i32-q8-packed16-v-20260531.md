# I32 packed16 DOT4 + q8_0 V validation — 2026-05-31

## Goal

Add/confirm a higher-precision V option for users who want more precision than q4_0 V while staying on the I32 packed16 DOT4/MMQ FlashAttention route.

Target profile:

```text
K: packed16 q8/i8 in I32 + f16 scales = 8.5 bits/value
V: q8_0 payload + f16 scales = 34B/32 values = 8.5 bits/value
combined K+V = 17 bits/value-pair
```

This is larger than packed16-K + q4-V:

```text
q4 V: K 8.5 + V 4.5 = 13 bits/pair
q8 V: K 8.5 + V 8.5 = 17 bits/pair
```

but q8 V is still smaller than packed16-K + f16-V:

```text
packed16-K + f16-V = 8.5 + 16 = 24.5 bits/pair
```

## Code status

The q8_0 V path was already wired in the packed16 DOT4/MMQ implementation:

```text
ggml/src/ggml-cuda/fattn-packed16-dot4-mmq.cuh
```

Existing support points:

```text
PACKED16_DOT4_MMQ_V_Q8_0
pdmq_decode_v_q8_0(...)
ggml_cuda_packed16_dot4_mmq_v_supported(GGML_TYPE_Q8_0)
PDMQ launch cases for GGML_TYPE_Q8_0
```

The prior q4 route-require fix also made `GGML_CUDA_FA_ROUTE_REQUIRE=rocm_packed16_dot4_mmq` a hard contract for q8_0 V decode, including `nq == 1`.
